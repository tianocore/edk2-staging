# EFI Authenticated Variable Update Tool

## Overview

This tool is used to generate EFI Authenticated Variable Update files (.auth), allowing updates to Secure Boot variables (PK, KEK, DB, DBX) in **User Mode (Standard Mode)**.

## How It Works

```
Certificate File (MLDSA-KEK.cer)
    ↓
Create EFI_SIGNATURE_LIST
    ↓
Prepare data to sign (VariableName + GUID + Attributes + TimeStamp + Data)
    ↓
Call SignTool.exe to generate PKCS#7 signature
    ↓
Assemble EFI_VARIABLE_AUTHENTICATION_2 structure
    ↓
Output .auth file
```

## File Structure

The generated `.auth` file contains a complete `EFI_VARIABLE_AUTHENTICATION_2` structure:

```
[16 bytes] EFI_TIME (Timestamp)
[variable] WIN_CERTIFICATE_UEFI_GUID
    ├─ [4 bytes] dwLength
    ├─ [2 bytes] wRevision (0x0200)
    ├─ [2 bytes] wCertificateType (0x0EF1)
    ├─ [16 bytes] CertType (gEfiCertPkcs7Guid)
    └─ [variable] PKCS#7 SignedData (generated by SignTool)
[variable] EFI_SIGNATURE_LIST (contains certificate)
```

## Requirements

### Required Tools

1. **Python 3.7+**
   - Built-in libraries, no additional packages needed

2. **Microsoft SignTool.exe**
   - From Windows SDK
   - Download: https://developer.microsoft.com/windows/downloads/windows-sdk/
   - Typical installation path: `C:\Program Files (x86)\Windows Kits\10\bin\<version>\x64\signtool.exe`

### Required Files

1. **Certificate files** (.cer, DER format)
   - MLDSA-KEK.cer - KEK certificate
   - db.cer - DB certificate
   - etc.

2. **Signing keys** (.pfx, PKCS#12 format)
   - MLDSA-PK.pfx - Used to sign KEK updates
   - MLDSA-KEK.pfx - Used to sign DB updates
   - Must contain both private key and certificate

## Usage

### Basic Syntax

```powershell
python generate_auth_var.py --cert <cert_file> --key <pfx_file> --password <pwd> --var-name <variable> --output <output_file>
```

### Parameter Description

| Parameter | Description | Example |
|-----------|-------------|---------|
| `--cert` | Certificate file (DER format) | `MLDSA-KEK.cer` |
| `--key` | Signing key (PKCS#12) | `MLDSA-PK.pfx` |
| `--password` | Key password (optional) | `mypassword` |
| `--var-name` | Variable name | `KEK`, `db`, `PK`, `dbx` |
| `--output` | Output file | `MLDSA-KEK-MLDSA.auth` |

### Example 1: Generate MLDSA-KEK-MLDSA.auth

Update KEK variable, signed with PK:

```powershell
python generate_auth_var.py ^
    --cert ..\Key\MLDSA-KEK.cer ^
    --key ..\Key\MLDSA-PK.pfx ^
    --password "your_pk_password" ^
    --var-name KEK ^
    --output ..\AuthVars\MLDSA-KEK-MLDSA.auth
```

**Explanation**:
- MLDSA-KEK.cer is the new KEK certificate to be written
- MLDSA-PK.pfx contains the currently installed PK private key
- In User Mode, only PK can sign KEK updates

### Example 2: Generate db.auth

Update DB variable, signed with KEK:

```powershell
python generate_auth_var.py ^
    --cert ..\Key\db.cer ^
    --key ..\Key\MLDSA-KEK.pfx ^
    --password "your_kek_password" ^
    --var-name db ^
    --output ..\AuthVars\db.auth
```

**Explanation**:
- DB can be signed by either KEK or PK
- Typically KEK is used to sign DB updates

### Example 3: Generate MLDSA-PK.auth

Update PK variable, signed with old PK:

```powershell
python generate_auth_var.py ^
    --cert ..\Key\PK_new.cer ^
    --key ..\Key\PK_old.pfx ^
    --password "your_old_pk_password" ^
    --var-name PK ^
    --output ..\AuthVars\MLDSA-PK.auth
```

**Explanation**:
- PK can only be signed by the current PK
- Used for PK key rotation

## Signing Rules

| Variable | Valid Signing Keys | Notes |
|----------|-------------------|-------|
| **PK** | Current PK | Can only be self-signed by current PK |
| **KEK** | PK | Can only be signed by PK |
| **DB** | KEK or PK | Typically signed with KEK |
| **DBX** | KEK or PK | Typically signed with KEK |
